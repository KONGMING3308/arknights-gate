# 04 · 数据模型

> 本文件的实体字段表与 `src/types/index.ts` **逐字段一致**；接口表与 `src/api/gameApi.ts` 的四个函数一一对应。
> 若类型源文件变更，本文件必须同步更新。

---

## 一、类型别名

| 类型名 | 定义 | 说明 |
|---|---|---|
| `Day` | `1 \| 2 \| 3 \| 4 \| 5` | 游戏天数，硬上限 5 |
| `ApplicantKind` | `'operator' \| 'impostor' \| 'anomaly'` | 申请人真实身份：正常干员 / 入侵者 / 无法判定的异常存在（普瑞塞斯） |
| `VerdictAction` | `'approve' \| 'reject'` | 玩家可执行的两种处置：批准 / 拒绝。**射击系统已移除，不再有 `execute`** |
| `Phase` | `'title' \| 'review' \| 'dayEnd' \| 'ending'` | 游戏阶段 |
| `StampType` | `'clear' \| 'smudged' \| 'missing'` | 通行证印章状态：清晰 / 模糊 / 缺失 |
| `DossierStatus` | `'active' \| 'missing' \| 'revoked'` | 档案状态：在册 / 查无此人 / 已注销 |

## 三、Store 扩展类型

`src/store/gameStore.ts` 在 `GameState` 基础上扩展了以下字段与方法（不属于 `types/index.ts`，记录于此供完整参考）：

### 3.1 LastOutcome（上次处置结果）

| 字段名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `codeName` | `string` | 是 | 干员代号 |
| `action` | `VerdictAction` | 是 | 处置动作（仅 approve/reject） |
| `kind` | `ApplicantKind` | 是 | 真实身份（含 anomaly） |
| `correct` | `boolean` | 是 | 是否正确 |
| `safetyDelta` | `number` | 是 | 安全度变化 |
| `trustDelta` | `number` | 是 | 信任度变化 |

### 3.2 GameStore 方法

| 方法 | 说明 |
|---|---|
| `startGame()` | 重置为初始状态，`phase` 置 `'review'` |
| `resumeGame()` | 从 localStorage 存档恢复，`phase` 置 `'review'`（不重置数值） |
| `toggleHints()` | 切换 `hintsEnabled` |
| `applyVerdict(applicantId, codeName, kind, action, recommenderValid)` | 结算数值、写记录、判定失败；`kind='anomaly'` 时返回 0/0/correct=true |
| `advanceSlot()` | 推进下一人；若已到最后一人则 `phase='dayEnd'` |
| `goNextDay()` | 进入下一天；若 `day >= UNLOCKED_DAYS` 则 `phase='ending'` |
| `penalize(safetyDelta, trustDelta)` | S.W.E.E.P. 失败时额外扣减数值（不写记录） |
| `reset()` | 重置为初始状态 |

> Store 已用 Zustand `persist` 中间件持久化到 localStorage（key `arknights-gate-save`），`partialize` 仅持久化 `day/slotIndex/safety/trust/records/hintsEnabled`（不持久化 `phase` 与 `lastOutcome`）。

## 四、接口表（对应 `src/api/gameApi.ts` 四个函数）

所有函数内部按 `VITE_USE_MOCK` 切换 Mock / 真实接口（`USE_MOCK = import.meta.env.VITE_USE_MOCK === 'true'`）。
Mock 模式下从 `src/mocks/index.ts` 汇总的数据（`ALL_APPLICANTS`/`ALL_PASSPORTS`/`ALL_DOSSIERS` + `getMockRoster`）取数；真实模式走 `request<T>` 经 `fetch` 调 `${API_BASE}${path}`。

| 方法 | 函数 | 路径（真实模式） | 入参 | 出参 | Mock 行为 | 错误码 / 错误情形 |
|---|---|---|---|---|---|---|
| GET | `fetchDayRoster` | `/days/:day/roster` | `day: number` | `Promise<Applicant[]>` | `sleep(200)` 后 `getMockRoster(day)`；按天从 `ALL_APPLICANTS` 过滤并按 slot 排序；命中 `ANOMALY_DAY` 时插入普瑞塞斯并重排 slot。固定名单 32 人 + 异常 1 人 = 最多 33 人 | 真实模式：HTTP 非 2xx 抛 `请求失败：{status} {path}` |
| GET | `fetchPassport` | `/passports/:applicantId` | `applicantId: string` | `Promise<Passport>` | `sleep(150)` 后查 `ALL_PASSPORTS[applicantId]`（含 5 天全部通行证 + 普瑞塞斯） | Mock：未命中抛 `通行证不存在：{applicantId}`；真实模式：HTTP 非 2xx 抛错 |
| GET | `fetchDossier` | `/dossiers/:codeName` | `codeName: string` | `Promise<Dossier>` | `sleep(800)`（`DOSSIER_FETCH_DELAY`）后查 `ALL_DOSSIERS[codeName]`（含 5 天全部档案 + 普瑞塞斯） | Mock：未命中抛 `档案查无此人：{codeName}`；真实模式：HTTP 非 2xx 抛错；路径含中文需 `encodeURIComponent` |
| POST | `submitVerdict` | `/verdicts` | `applicantId: string`, `action: VerdictAction` | `Promise<void>` | `sleep(120)` 后返回；真实模式 POST `{applicantId, action}` | 真实模式：HTTP 非 2xx 抛错 |

### 4.1 公共配置（`src/api/client.ts`）

| 配置项 | 来源 | 说明 |
|---|---|---|
| `USE_MOCK` | `import.meta.env.VITE_USE_MOCK === 'true'` | 是否使用 Mock 数据 |
| `API_BASE` | `import.meta.env.VITE_API_BASE_URL ?? ''` | 真实接口基址，默认空串 |
| `sleep(ms)` | 内联 | 模拟网络延迟 |
| `request<T>(path, init?)` | 内联 | 统一 JSON 请求，`Content-Type: application/json`；`!res.ok` 抛 `请求失败：{status} {path}` |

## 六、担保规则与突脸字段（F-22 / F-23）

| 名称 | 类型/取值 | 说明 |
|---|---|---|
| `Applicant.attacksWhenRejected` | `boolean?`（可选，默认 false） | 被「拒绝」时是否触发 S.W.E.E.P. 求援事件。当前为 D4 能天使、D5 推进之王、D5 变形者集群 |
| `Applicant.scrambled` | `boolean?`（可选，默认 false） | 所有证件字段为乱码（仅普瑞塞斯）；放行/拒绝均不计分，不触发 S.W.E.E.P. |
| `REGISTERED_OPERATORS` | `readonly string[]`（`src/constants/registry.ts`） | 本舰在册干员名录，作为「担保人是否有效」的判定依据 |
| `isRegisteredRecommender(codeName)` | `(string) => boolean` | 担保人是否在名录中 |
| `INVALID_SPONSOR_EFFECT` | `{approve:{safety:-15}, reject:{safety:+5}}` | 担保失效时的判定表（`src/utils/verdict.ts`）：拒绝一定正确、批准错误。**execute 分支已随射击系统移除** |

> 业务解释：派遣函写明「担保人须为在册干员，如有不实，担保人一并追责」。因此当担保人 C 不在名录时，
> 由 C 担保的 A、B 两人**都**不具备入境资格——设计为「程序性可拒绝」而非「连带定罪」，
> 玩家拒绝两人都判定为正确；若其中一人其实是正常干员，拒绝仍正确（因为手续无效），不会误伤信任度。

## 普瑞塞斯落点与视觉异常（F-25）

| 名称 | 类型/取值 | 说明 |
|---|---|---|
| `ANOMALY_PLACEMENT_KEY` | `'arknights-gate-anomaly'` | localStorage 键，保存本局普瑞塞斯落在第几天/第几个位置；避免刷新页面就换位置 |

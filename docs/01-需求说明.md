# 01 · 需求说明

> 本文件阐述「明日方舟 · 罗德岛入境审查」的产品背景、目标用户、痛点与用户故事。
> 用户故事末尾标注对应的功能编号，详见 [02-功能清单](./02-功能清单.md)。

## 一、产品背景

「明日方舟 · 罗德岛入境审查」是一款基于明日方舟世界观的同人网页游戏，玩法致敬《请出示证件》（Papers, Please）、《边境检察官》与《这不是你的邻居》。

玩家扮演罗德岛入境口岸的审查官，每天面对 3–5 名申请入境的干员或访客，其中混有不该进入本舰的入侵者。玩家需要比对「通行证 / 罗德岛人事档案 / 本人 / 对话」四类信息，找出日期、编号、照片、印章、职业等维度的矛盾，然后作出处置：批准入境、拒绝入境，或者——拔枪射击。

游戏共 5 天，约 20 名申请人，伪造手法逐日升级。玩家有两项数值：安全度（放走入侵者会下降）与信任度（误杀干员会下降），任一归零即被撤职失败；撑过 5 天则按两项残值之和给出通关评级。

- **题材来源**：明日方舟罗德岛世界观（同人，非官方）。
- **运行形态**：纯前端浏览器游戏，打开即玩，无需安装、无需后端（真实接口为预留，见 [04-数据模型](./04-数据模型.md) 接口表）。
- **内容形式**：手工剧本约 20 人，身份、伪造点、台词固定，重玩内容不变；存档用 localStorage。

## 二、目标用户

| 用户画像 | 描述 |
|---|---|
| 核心玩家 | 明日方舟受众中喜欢「请出示证件」式审查玩法的玩家，对干员身份有认知，能从代号、出身、推荐人等细节中获得代入感 |
| 次核心玩家 | 喜欢轻量推理 / 文字审查类小游戏、但未必熟悉明日方舟的玩家，靠游戏内提示也能玩 |
| 用户特征 | 非技术人员为主，习惯浏览器打开即玩，对复杂安装、账号注册有抵触；偏好短局（单局约 15–25 分钟） |

---

## 三、用户痛点

| 编号 | 痛点 | 说明 |
|---|---|---|
| P-1 | 同人审查类游戏稀缺 | 明日方舟题材缺少「请出示证件」式的沉浸式审查体验，现有同人多为卡牌或塔防 |
| P-2 | 重玩内容随机导致无法精进 | 部分审查游戏靠程序生成，玩家无法靠记忆与经验提升；本游戏用固定剧本，让玩家能逐步掌握每个伪造点 |
| P-3 | 处置手段过于极端 | 传统审查游戏往往只有「放行 / 拒绝」两极；本游戏加入「拔枪」与「拒绝」中间档，提供更丰富的道德张力与判断空间 |
| P-4 | 安装与上手门槛高 | 许多游戏需下载安装、注册账号；本游戏纯前端打开即玩，降低门槛 |
| P-5 | 难度无梯度 | 部分游戏破绽难度一刀切；本游戏按天递进伪造手法（D1 印章糊 → D5 多重破绽），给玩家学习曲线 |

## 四、用户故事

每条用户故事采用「As a… I want… So that…」格式，末尾标注对应的功能编号（见 [02-功能清单](./02-功能清单.md)）。

| 编号 | 用户故事 | 对应功能编号 |
|---|---|---|
| US-01 | **作为一名**审查官玩家，**我想要**一个标题页介绍我的身份与规则，**以便**在开始前理解我要做什么、失败条件是什么。 | F-01 |
| US-02 | **作为一名**审查官玩家，**我想要**每天看到当天待审人员名单与我当前的安全度/信任度，**以便**随时掌握进度与风险。 | F-02、F-03 |
| US-03 | **作为一名**审查官玩家，**我想要**看到申请人的立绘并能询问代号、来意、推荐人三个问题，**以便**从对话中获取线索。 | F-04 |
| US-04 | **作为一名**审查官玩家，**我想要**查看申请人提交的通行证（编号、姓名、照片、日期、路线、印章），**以便**核对基本信息。 | F-05 |
| US-05 | **作为一名**审查官玩家，**我想要**主动调取罗德岛人事档案（带检索延迟），**以便**把通行证与档案逐项比对找矛盾。 | F-06、F-07 |
| US-06 | **作为一名**审查官玩家，**我想要**在比对材料时自行核对、破绽不自动标红，**以便**获得真实的审查挑战；但我希望有个「新手提示」开关在我卡住时给一点提示。 | F-08 |
| US-07 | **作为一名**审查官玩家，**我想要**三种处置手段——批准、拒绝、拔枪——且任何时候都能开枪，**以便**根据判断作出不同力度的处置，并承担误杀的代价。 | F-09、F-10 |
| US-08 | **作为一名**审查官玩家，**我想要**在拔枪时有举枪、确认、开火的完整动画与不可撤回的提示，**以便**感受到这一枪的分量。 | F-10 |
| US-09 | **作为一名**审查官玩家，**我想要**每次处置后看到数值变化与判断正误，**以便**知道我这次做对了还是做错了。 | F-11 |
| US-10 | **作为一名**审查官玩家，**我想要**一天结束时看到当日处置记录与数值变化汇总，**以便**复盘今日表现。 | F-12 |
| US-11 | **作为一名**审查官玩家，**我想要**安全度或信任度归零时立即进入失败结局，**以便**清楚知道自己为何被撤职。 | F-13 |
| US-12 | **作为一名**审查官玩家，**我想要**撑过 5 天后看到最终数值与评级（S/A/B/C/D），**以便**有通关成就感与重玩动力。 | F-14 |
| US-13 | **作为一名**新手玩家，**我想要**伪造难度逐日递进（D1 印章糊 → D5 多重破绽），**以便**有学习曲线而不是一开始就被难住。 | F-15 |
| US-14 | **作为一名**重玩玩家，**我想要**剧本固定、存档能继续上次进度，**以便**靠记忆与经验精进，而不是每次重来。 | F-16 |

## 五、非目标（明确不做的事）

| 项 | 说明 |
|---|---|
| 战斗场景 | 拔枪后中枪即消灭，无战斗、无血条、无回合制 |
| 后端服务 | 当前为纯前端 + Mock；真实接口仅预留签名，M2 不强制实现后端 |
| 程序生成内容 | 剧本手工固定，不做随机生成 |
| 多语言 | 仅中文 UI |
| 移动端原生 App | 仅浏览器，不做原生打包 |
| CodexScreen（图鉴） | HANDOFF.md 列为 P2，当前未实现，不在 M1/M2 必做范围 |

## 二、文字流程图

### 2.1 主流程

```
[TitleScreen]
   │
   ├─ 点击「开始值班」 ──> store.startGame() ──> phase='review' ──> /review
   └─ 点击「继续上次」 ──> store.resumeGame() ──> 从 localStorage 恢复 ──> phase='review' ──> /review
                                                       │
                                                       ▼
                                              [ReviewScreen] ◄────┐
                                                       │            │
                                  ┌────────────────────┼────────────┤
                                  ▼                    ▼            ▼
                            点击批准              点击拒绝      （无拔枪入口）
                          settle('approve')    settle('reject')
                                  │                    │
                                  │           attacksWhenRejected?
                                  │             ├─ true ──> SweepEvent（9s/10tap）
                                  │             │              ├─ 成功 ──> doSettle('reject')
                                  │             │              └─ 失败 ──> penalize(-15,0) → doSettle('reject')
                                  │             └─ false ──> doSettle('reject')
                                  │                    │
                                  └─────────┬──────────┘
                                            ▼
                              applyVerdict() 结算数值 + 记录
                                            │
                              ┌─────────────┼─────────────┐
                              ▼                           ▼
                    safety≤0 或 trust≤0            数值未归零
                    phase='ending'                 advanceSlot()
                              │                           │
                              ▼                  ┌────────┴────────┐
                         /ending                ▼                 ▼
                                       slotIndex+1 >= ROSTER_SIZE  还有下一人
                                       phase='dayEnd'             slotIndex+1
                                              │                 继续 ReviewScreen
                                              ▼                       (回到上方)
                                       [DayEndScreen]
                                              │
                                    点击「进入下一天」
                                              │
                                              ▼
                                    store.goNextDay()
                                              │
                                ┌─────────────┴─────────────┐
                                ▼                           ▼
                          day >= UNLOCKED_DAYS(5)      day < 5
                          （第 5 天，查看评级）       （第 1–4 天，进入下一天）
                          phase='ending'               day+1, slotIndex=0
                                │                      phase='review'
                                ▼                          │
                           /ending                        ▼
                                                  回到 ReviewScreen
```

### 2.2 失败与结局分支

```
任意处置后 applyVerdict():
  safety ≤ 0 ──> phase='ending' ──> /ending ──> 显示 FAIL_TEXT.safety（安全度归零）
  trust ≤ 0 ──> phase='ending' ──> /ending ──> 显示 FAIL_TEXT.trust（信任度归零）

第 5 天全部审完且数值未归零:
  goNextDay() 中 day>=UNLOCKED_DAYS(5) ──> phase='ending' ──> /ending ──> 显示评级 + 最终数值
```

### 2.3 单人审查内部流程（ReviewScreen 内）

```
进入 /review (day 变化)
   │
   ├─ fetchDayRoster(day) ──> roster[]（含普瑞塞斯异常插入）
   │
   └─ applicant = roster[slotIndex]
        │
        ├─ fetchPassport(applicant.id) ──> passport (展示在中栏 DocumentTray)
        │
        ├─ 玩家点击「代号/来意/推荐人」 ──> handleAsk ──> 显示回答 + 标记已问 + playTick
        │
        ├─ 玩家点击「调取档案」 ──> handleFetchDossier
        │       └─ fetchDossier(codeName) (延迟 800ms) ──> dossier (展示在右栏 DossierPanel)
        │       └─ 若 applicant.scrambled=true，DossierPanel 显示「校验失败：该申请人的全部字段无法解析。」
        │
        ├─ 玩家自行比对（不自动标红；hintsEnabled 开启时 DossierPanel 显示破绽计数）
        │
        └─ 玩家选择处置:
              ├─ 批准 ──> settle('approve') ──> doSettle('approve')
              └─ 拒绝 ──> settle('reject')
                          ├─ applicant.attacksWhenRejected=true ──> SweepEvent
                          │     ├─ 9s 内连点 10 次 ──> success ──> doSettle('reject')
                          │     └─ 超时 ──> fail ──> penalize(-15,0) ──> doSettle('reject')
                          └─ 否则 ──> doSettle('reject')

doSettle() 后:
  submitVerdict + applyVerdict ──> 1400ms 后 advanceSlot()
```

## 三、各页元素与交互

### 3.1 TitleScreen（`/`）

| 区域 | 元素 | 交互 | 文案来源 |
|---|---|---|---|
| 标题区 | APP_TITLE / APP_SUBTITLE | 静态展示 | `copy.ts` |
| 介绍区 | 三行 intro 文案 | 静态展示 | `TITLE_SCREEN.intro` |
| 警告区 | 失败条件警告 | 静态展示 | `TITLE_SCREEN.warning` |
| 操作区 | 「开始值班」按钮 | 点击 → `startGame()` → 跳转 `/review` | `TITLE_SCREEN.start` |
| 操作区 | 「继续上次」按钮 | 点击 → `resumeGame()` → 跳转 `/review`（从 localStorage 存档恢复） | `TITLE_SCREEN.continue` |

### 3.2 ReviewScreen（`/review`）—— 核心

**布局**：`grid-cols-[330px_1fr_360px]`，三栏 + 顶部 header + 底部 ActionBar。

| 区域 | 子组件 | 元素与交互 |
|---|---|---|
| 顶部 header | StationHeader + StatBar×2 | 左：站台信息条（第 N 日 / 待审 X/Y）；右：安全度条（蓝）、信任度条（绿） |
| 左栏 | ApplicantWindow | 申请人立绘（`portrait`）、代号、种族、出身、职业；下方三个问题按钮「代号/来意/推荐人」，点击显示 `dialogue[].answer` 并标记「已问」；点击触发 `playTick` 提示音 |
| 中栏 | DocumentTray（含 PassportCard + DispatchLetter） | 通行证（PassportCard）：编号、姓名、照片、签发日期、有效至、路线、印章状态、印章机构文字；派遣函（DispatchLetter）：申请人来意/派遣信息 |
| 右栏 | DossierPanel | 「调取档案」按钮（点击 800ms 延迟后展示档案：代号、编号、职业、出身、推荐人、照片、档案状态、要求印章）；未调档时显示 `dossierEmpty`；加载中显示 `dossierLoading`；`hintsEnabled` 开启时显示破绽计数（`discrepancyCount`）；若 `applicant.scrambled=true` 则显示「校验失败：该申请人的全部字段无法解析。」 |
| 底部 | ActionBar | 「批准入境」「拒绝入境」两按钮（**射击系统已移除，无拔枪按钮**）；处置后展示 `lastOutcome`（正误 + delta）；`busy` 时禁用；支持快捷键 1/2（批准/拒绝） |
| 覆盖层 | SweepEvent | 当 `settle('reject')` 命中 `attacksWhenRejected=true` 的入侵者时全屏展示：多只黑色手剪影（红色轮廓光，`animate-reach` 循环）从各方向伸向屏幕；顶部 HUD 显示袭击者代号与进度条；底部「呼叫 S.W.E.E.P.」按钮，9 秒内连点 10 次。成功：阿斯卡纶立绘（`ascalon.png`）登场 + 「非法入侵的变形者已被处决」通告（2.6s 后关闭）；失败：闪红 + 「增援未能及时抵达」（1.4s 后关闭），额外扣安全 15 |
| 音效 | audio.ts | 处置时触发：`approve`/`reject`→`playStamp`（盖章）；询问点击→`playTick`；**枪声合成已随射击系统移除** |

> 快捷键由 `src/hooks/useHotkeys.ts` 提供：1 批准 / 2 拒绝；输入框聚焦时不拦截。**原 3/Esc 拔枪/收枪快捷键已移除**。

### 3.3 DayEndScreen（`/day-end`）

| 区域 | 元素 | 交互 | 文案来源 |
|---|---|---|---|
| 标题 | 「今日值班结束」 | 静态 | `DAY_END.title` |
| 数值变化 | 安全度变化 / 信任度变化 | 静态展示当日 delta | `DAY_END.safetyDelta` / `trustDelta` |
| 处置记录 | 当日每人的代号、处置、正误 | 静态列表 | `DAY_END.records` + `RESULT_TEXT` |
| 操作 | 下一天 / 查看评级按钮 | 第 1–4 天（`day < UNLOCKED_DAYS`）显示「进入下一天」→ `goNextDay()` → `/review`（day+1）；第 5 天（`day >= UNLOCKED_DAYS`）显示「查看评级」→ `goNextDay()` → `/ending` | `DAY_END.next` / `DAY_END.final` |

### 3.4 EndingScreen（`/ending`）

| 区域 | 元素 | 交互 | 文案来源 |
|---|---|---|---|
| 标题 | 「审查结束」 | 静态 | `ENDING.title` |
| 失败分支 | safety 归零文案 / trust 归零文案 | 根据 store 状态展示 | `FAIL_TEXT.safety` / `trust` |
| 通关分支 | 评级（S/A/B/C/D）+ 最终安全度 + 最终信任度 | 按 `computeGrade(safety+trust, RATING_THRESHOLDS)` 计算 | `ENDING.grade` / `safety` / `trust` |
| 操作 | 「重新值班」按钮 | 点击 → `reset()` → `/` | `ENDING.restart` |

## 四、路由表（与 `src/App.tsx` 一致）

| 路径 | 组件 | 说明 |
|---|---|---|
| `/` | TitleScreen | 标题页 |
| `/review` | ReviewScreen | 审查页 |
| `/day-end` | DayEndScreen | 当日结算 |
| `/ending` | EndingScreen | 结局 |
| `*` | Navigate → `/` | 兜底重定向 |

页面跳转由 `useGameStore` 的 `phase` 驱动：ReviewScreen 内 `useEffect` 监听 `phase`，`dayEnd` → `/day-end`，`ending` → `/ending`。

## 覆盖层（非路由）

| 组件 | 位置 | 触发 | 说明 |
|---|---|---|---|
| `SweepEvent` | ReviewScreen 内 Portal（z-[120]） | `settle('reject')` 命中 `applicant.attacksWhenRejected=true` | 全屏求援事件：多只黑色手剪影（`reaching_hand.png`，红色轮廓光，`animate-reach` 循环）从各方向伸向屏幕；9 秒内连点「呼叫 S.W.E.E.P.」按钮 10 次。成功：阿斯卡纶立绘（`ascalon.png`）+ 处决通告，按 reject 结算（安全 +5）；失败：额外扣安全 15，仍按 reject 结算。参数见 `SWEEP` 常量 |

> **已移除的覆盖层**：`GunOverlay`（拔枪）、`AssaultScene`（FPS 射击）均随射击系统一并删除，不再存在。

> 审查页顶栏另有「破绽提示」复选框（F-24），控制右栏是否显示破绽计数。
